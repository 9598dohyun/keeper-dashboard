# 결제 데이터 엑셀 반영 절차

오전에 받는 결제 데이터 엑셀을 대시보드에 반영하는 순서.
자동 스케줄은 2026-08-26에 중단했고, 이 절차로만 갱신된다.

## 사전 준비

환경변수를 셸에 올린다 (한 번만).

```bash
cd /Users/dohyeon/Documents/업무/한화비전/keeper-dashboard
set -a && source ../.env && set +a          # AIRTABLE_TOKEN, AIRTABLE_SKB_BASE_ID
set -a && source .env.local && set +a       # KV_REST_API_URL, KV_REST_API_TOKEN
```

## 실행 (3단계)

```bash
# 1) 엑셀 ↔ 에어테이블 대조 → data/결제대조.json
python3 scripts/payment-sync/reconcile.py ~/Downloads/결제데이터.xlsx

# 2) 에어테이블 최신 데이터 수집 (응대·유입 집계용)
npx tsx scripts/fetch-airtable.ts

# 3) 지표 계산 → KV 저장 (대시보드에 반영)
npx tsx scripts/compute-and-push.ts
```

3단계까지 끝나면 대시보드에 바로 보인다.

먼저 확인만 하고 싶으면 1단계에 `--dry-run`을 붙인다 (파일을 쓰지 않고 대조 결과만 출력).

기준일을 엑셀 내용과 다르게 잡아야 하면 `--date 2026-08-26` 을 붙인다.
생략하면 엑셀에 담긴 결제일 중 가장 늦은 날짜를 기준일로 쓴다.

## 지표 기준

| 지표 | 기준 |
|------|------|
| 응대수 | 에어테이블 `메모수정시각`이 그날인 건 (메모를 남긴 것 = 응대한 것) |
| 결제수 | **결제 데이터 엑셀에 있는 건**. 엑셀에 없으면 `[콜]최종 결과`가 '결제 완료'여도 결제로 세지 않는다 |
| 유입 | 에어테이블 `유입시간` |

`data/결제대조.json`이 없으면 결제수가 에어테이블 `[콜]최종 결과` 기준으로 계산된다.
1단계를 건너뛰고 2·3단계만 돌리면 이 상태가 되므로, 결제수를 엑셀 기준으로 유지하려면
1단계를 매번 같이 돌린다.

## 대조 결과 읽는 법

실행하면 이런 항목이 나온다.

- **에어테이블 매칭** — 엑셀 결제 건이 에어테이블 리드와 연결된 수. 이 수가 대시보드 결제수가 된다
- **에어테이블 미매칭** — 엑셀에는 있는데 에어테이블에 리드가 없는 건. 리드 없이 결제된 경우이며 결제수에 반영되지 않는다. 계속 나오면 리드 유입 경로를 확인해야 한다
- **에어테이블만 결제 표기** — 에어테이블은 '결제 완료'인데 엑셀에 없는 건. 엑셀이 기준이므로 결제로 세지 않는다. 취소·미결제 건이거나 엑셀 누락이므로 수가 많으면 엑셀을 먼저 확인한다

대조 키는 **전화번호 뒷 8자리**다 (한화비전 중복 판정 기준과 동일).

## 엑셀 컬럼명이 바뀌었을 때

`전화번호 컬럼을 못 찾았습니다` 오류가 나면 `reconcile.py` 상단의 `PHONE_HEADERS`에
실제 컬럼명을 추가한다. `NAME_HEADERS`, `DATE_HEADERS`도 같은 방식이다.
헤더 행이 첫 줄이 아니어도(제목·머리말이 위에 붙어도) 30행 안에서 자동으로 찾는다.

## 개인정보

`data/결제대조.json`에는 이름·전화번호를 남기지 않는다 (에어테이블 레코드 ID와 건수만).
`data/`는 gitignore 대상이며, 콘솔 출력의 이름도 마스킹된다.

## 자동 스케줄을 되살릴 때

`.github/workflows/refresh-metrics.yml`, `keeper-reports.yml`의 `schedule` 블록 주석을 해제한다.
단 자동 실행은 엑셀 대조를 거치지 않으므로 결제수가 에어테이블 기준으로 돌아간다.
